# Security Policy

This project values security and works to keep its codebase safe. If you find any security vulnerability or potential exploit, please follow the process outlined below.

## 🚨 Reporting a Vulnerability

**DO NOT** discuss the details of a vulnerability on public forums or through public issue trackers unless directed to do so by the maintainers.

1. **Report Privately:** Please report all security vulnerabilities directly to the project maintainers via a private channel (e.g., a dedicated security email address or a private GitHub issue). *[Maintainer Note: Please replace this placeholder with an actual private contact method.]*
2. **Provide Details:** When reporting, please include:
   * A clear description of the vulnerability.
   * The affected component, function, or file.
   * A proof-of-concept (PoC) exploit, if possible, that demonstrates the issue without causing undue harm.
   * The potential impact of the vulnerability.
3. **Scope:** Please confirm that the vulnerability is not already known or addressed.

## 🛡️ Responsible Disclosure

We practice **Responsible Disclosure**. This means we will work with you in private to validate the vulnerability and develop a patch before releasing any public information about it. Our goal is to fix the issue and release a secure update to the community simultaneously.

## 🤝 Contribution

If you find an issue, please open a regular issue on the repository issue tracker. If the issue is security-related, please escalate it immediately to the private channel.

Thanks to all contributors who help keep this project secure!
